# Native NEST weather reports

`weather.html`, `js/weather-form.js`, and `js/weather.js` provide the native check-in, division reporting, and administrator archive. The supplied Emotion–Sensation Wheel retains Lindsay Braman attribution. Rebuild the SVG/catalog/GAS validation catalog together with `python3 scripts/build-weather-wheel.py <original.svg>`.

The authenticated `/api/weather-native` endpoint forwards selected fields to the school service's `auth-weather-native` action. The school service resolves the account's linked school email against `CombinedStudentList!A2:E1000` in the enrolled-student master workbook. The directory is a read-only input; it is never returned to clients. Repeated imports and multiple course titles for the same student email, name, student ID, and period count as one identity. When course titles differ, reports use the shared Division number. Conflicting names or student IDs for the same email and period still fail closed. Manual usernames resolve through the active account’s Linked Student Email and current allowed-period roster; a shared Recovery Email never grants student identity or owner access. An unmatched student cannot submit or confirm under an invented identity.

Hover previews an emotion through a pointer-transparent magnifying overlay on the wheel. Click/tap immediately selects and confirms it, dismisses the lens, and keeps the confirmed answer stable during later hovering. Administrator accounts without an enrolled record receive an explicit full-form test mode with all division choices and enabled ratings. Seven server-allowlisted sample surnames in test mode preview counselor matching and direct scheduling links without creating alerts; the same selected surname is used on emotion confirmation. Students cannot override their enrolled surname. Confirmations alone create no alerts; an explicit test support request creates an owner-only synthetic alert; completion validates the same fields and confirmation receipt but never appends a student report. Test status is derived from the authenticated owner and enrollment lookup, never a client-supplied flag. The wheel supports arrow-key navigation and Enter/Space confirmation for keyboard users. There is no separate emotion dropdown or confirmation button. Every emotion family opens optional next-step suggestions and the student’s own counselor scheduler (or the existing reliable directory fallback). The suggestions are everyday coping options adapted from CDC stress-management and American Academy of Pediatrics teen guidance; the page links both sources. Selecting an emotion, opening a counselor scheduler, checking a recipient box, or submitting a report never creates an alert. A separate Request support button sends a durable notification only to the roles the student selects: Mr. Penalver, division manager, assistant manager, and/or partner liaison. All choices begin unchecked. The remaining report is saved only on submit. Confirmation and submission IDs prevent duplicates, including recovery after a partially completed request. Different support requests have a 10-second rate limit. A support request binds the confirmed emotion and period to its draft; retries reuse the same recipient choices and cannot duplicate the alert. Alert acknowledgements store only event IDs locally; report content and student details are not persisted in browser storage.

New Reports, Alerts, and Confirmations are retained in a separate private workbook identified by the `weather-native-store` script property. The first owner bootstrap provisions it and installs a daily school-counselor refresh trigger. Existing Google Form history stays in its original workbook and is merged on read. Native submissions use RAW writes. Storage reads currently fail explicitly at 19,999 native rows/confirmations/alerts or 9,999 legacy rows, rather than silently dropping older records; expand pagination before those limits are reached. The student directory input is currently bounded to row 1000.

Only owner aliases can export, manage school calendars, refresh counselors manually, or create test alerts. Division managers, assistant managers, and partner liaisons may read only their own division. Support alerts go only to the student-selected roles, with role holders rechecked against the current division leadership. Assistant managers receive an alert only when that role was selected. Alerts without a stored explicit recipient selection from the older automatic system remain in the private ledger but no longer surface in notification polling. General executive roles alone do not grant weather access. Both the native and legacy weather readers enforce this policy.

Report controls share compact Division, School year, and Trimester dropdowns. Initial selections use the current school year and trimester from the school service. Changes fetch immediately, reset pagination, and ignore superseded responses. The administrator archive adds All divisions to the same selector.

Pacing and Grit dials use qualitative endpoints and “Just Right!” at the midpoint. Safety retains its numeric score toward 5. Raw averages remain available in the report table and exports, with their target values stated explicitly.

`js/weather-alerts.js` is loaded from the shared NEST main script. Alerts appear in a prominent amber panel at the top center, with the student name, emotion, current counselor scheduler (or counseling-directory fallback), and a tel:+12538006176 office-call link. New alerts retain the enrollment-derived surname to resolve updated counselor ranges on read; older records use their Lastname, Firstname display name when available. It checks for alerts every eight seconds while the page is visible, so on-screen delivery normally follows an explicit support request within several seconds plus school-service latency. Empty polls validate the durable session without reading spreadsheets or returning student data. New events always recheck the active account and current leadership permissions. Tests create labeled synthetic events visible only to the initiating owner account, never a student report or a notification to division leaders.

Counselors are parsed from the school's published counselor paragraphs, with validated surname ranges and allowlisted HTTPS appointment hosts. Last names are normalized for accents and punctuation. Unknown, ambiguous, stale (more than seven days), or invalid mappings show the school counseling directory instead of a guessed assignment. Daily refresh retains the last successful mapping and reports failures in the administrator panel.

School year runs August–July for year grouping. Trimester labels use explicit administrator-configured dates, seeded with the published 2026–2027 calendar. When no explicit school-year end or third-trimester ending event exists, import uses June 30 of the ending year, as authorized by the administrator. Conflicting explicit dates still require review. Older years without dates remain searchable/exportable with trimester “Unassigned”; importing the actual dates from the specified school Google calendar, recognizing MS/HS trimester endings and ordinal/abbreviated titles or entering them manually recalculates labels on read.

Exports are private school-owned workbooks with response data, rating/emotion charts, and a printable report tab. Spreadsheet and PDF download links require the school Google account that owns the service; files are never shared publicly or with division leaders. XLSX formula-like text is escaped. The PDF exports the printable tab with both charts and full written responses. Exports create retained private snapshots; they do not alter the original directory, legacy archive, or native records.

# Division HQ

Command → Division HQ opens `/divisions`, the division chooser. `/divisions/1` through `/divisions/7` (excluding 6) and `/divisions/CTSO` are dedicated member-only division pages. `/control-center` redirects to Division HQ, and the old `?division=` links remain compatible with bookmarks. The former Control Center chooser file is removed. Every division page includes the standard NEST logo and eagle menu, date, Quick Access, QR code, copyright, Help & Support and About Me. Command links navigate to each division home, with the current leadership assignments and position slide buttons above the manager slideshow. Every member gets an application link; managers and assistants also get the division-specific hiring link. A position opens its own dialog: assigned leaders and their division's managers/assistants get the Google Slides editor; other division members get the slideshow viewer. Manager-deck editing follows the same manager/assistant rule. Google sign-in must use the school account that holds the Drive permission.

`api/division-page.mjs` checks membership before returning any protected page content and embeds the authorized configuration to avoid repeating the first data request. It returns a sign-in page for 401, a locked page for 403, and a retry page for temporary service failures. Responses are private and never cached. `api/division.mjs` checks a server-verified NEST session and live division roster before returning any deck configuration. The school bridge resolves manual accounts to their roster-linked district email. Live roles determine editing and slide-update privileges; CTSO CEO/EVP are the management equivalents. NEST owners retain administrative access. No public browser script contains the deck catalog. Role windows recheck membership and assignments when opened. Authentication changes and leaving the page clear embedded resources. The school bridge loads the leadership table once and returns only current members of the selected division.

`google-control-center/DivisionSlideAccess.js` reconciles and audits actual Google permissions. Limited-access boundaries on the common folder and each division block inherited access from older parent folders; each division and its leadership subfolder grant roster members view access. Decks allow only roster members to view and assigned role holders plus management to edit. Legacy public, domain, group and outsider permissions are removed. Owners remain. A confirmed empty roster removes former member grants and retains owner access. An unavailable sheet or a malformed nonempty roster stops reconciliation before changing that division; an unexpected inherited or broad permission fails the audit. The former 3d Print Specialist name maps to Fabrication Supervisor.

Copy this helper into both the Control Center bound script and the existing daily leadership-sharing script. Replace only the latter's `updateDivisionFolderPermissions_safe_` implementation with `google-leadership/DivisionSlideAccessHook.js`. Keep all other daily leadership tools and triggers. Enable the existing Drive advanced service v2 in Control Center. Run `nestSyncAllDivisionSlideAccess` as the school owner and verify all seven division summaries before releasing the website. It checkpoints one division at a time and uses a temporary one-minute continuation trigger, which removes itself when complete. Interrupted runs resume the current division. It updates sharing only, without rebuilding any deck.

Load division slides runs the existing sheet routine through an authenticated owner-run queue. It preserves the first title slide, loads position decks in their established order, and applies the same division sharing policy. The bridge and queue recheck live roster/management roles, including when work starts. `authorizeNestDivisionWeb` installs the one-minute worker. The protected webapp checks the existing bridge-token digest; never expose the token in browser code.

Jobs are idempotent by UUID. Concurrent jobs for one division are rejected. The division page remembers its job ID and resumes progress after refreshing; leaving does not cancel work. Terminated executions become failed after ten minutes. The original sheet B2 becomes Slides Updated on completion. The legacy sheet/menu routine shares the queue's script lock.

Tests cover access denial before embedding, role-specific editors and manager overrides, queue recovery, server request validation, stale-role revocation, alias handling, permission reconciliation and inherited-access audit failures. Production verification does not rebuild real division decks merely to test the button.

## Hiring partners and interview workspace

`/hiring?period=…#manager-hiring` uses the available window width. Each position has an Add partner selector, including unfilled divisions. It reuses a vacant slot or appends rows beyond the original 18 slots; there is no single-person limit per position. Existing assignments can still be replaced. Every mutation validates the current manager/assistant (CTSO CEO/EVP), division membership and selected student against the current roster. Duplicate partner requests are idempotent; stale replacements fail without overwriting another assignment. Owners retain administrative access.

Assignments are saved to Division Team B:D, exported F:H, and the central Imported leadership directory. `google-leadership/HiringImportHook.js` replaces only the existing daily importer so appended rows survive the daily refresh. All role and slide-sharing reads include the full leadership table. A protected `sync-access` request queues the division's Google slide permissions on the existing permanent worker; it does not rebuild slides. The worker retains a newer sharing request that arrives during reconciliation. Queue failures leave the saved team intact and report that the daily sharing job will refresh access.

Each application has saved Notes (the existing Applications H column) and four nullable 1–4 interview ratings: role knowledge, communication, problem-solving, and teamwork. The total is calculated out of 16; partial totals identify unrated criteria. Criteria and the four rating levels are explained beside the table. The internal hidden NEST Interview Reviews tab is provisioned for all seven divisions (and recreated if missing), with application key, ratings, timestamp and editing account. Application keys derive from the original seven application fields, so notes/ratings are checked against the application rather than a browser-supplied row number. Duplicate keys, moved/changed identities and stale note/rating revisions fail safely. Notes and ratings save together in one workbook update; notes are literal strings, including text starting with `=`. Review-only CTSO executives cannot edit. The browser never stores notes or ratings locally.

Column and row resize handles support pointer dragging and arrow keys. Fit columns to window restores the responsive defaults; narrow windows retain horizontal scrolling. Layout sizes persist locally per signed-in manager and division. Unsaved reviews disable pagination, reloading and team changes until saved or reset. Sign-out and page exit clear the private workspace; returning from the browser's page cache rechecks access.

## Loading and navigation

Read-only division, hiring and directory requests fetch the current account/roster cells together and fetch leadership cells in parallel. These values are reused only inside that one school request, then discarded. No cross-request membership or role cache is introduced; writes continue to read current permissions. A failed parallel read falls back to live Sheets reads. Division HTML initializes NEST identity from its authorized bootstrap. Direct division hiring links initialize identity and the first applications page from a single authorized response, then consume that data once. Reloads and later actions still reach the server. School-read timing is available through Server-Timing and server logs without names, emails, sessions or application content.

The top-left eagle menu contains the current Command → Division HQ destination and the existing Leadership & Management and Robotics utilities. It initializes from the small generated public navigation embedded in `js/eagle-menu.js`, without fetching the entire homepage first. Run `node scripts/sync-eagle-menu.mjs` after changing the homepage's gear links. Tests compare every corner-menu destination with the homepage and reject obsolete Control Center/Division Folders entries.

# NEST Signals access

`signals.gknest.org` forwards to `https://gknest.org/signals` in the same tab. The entry page uses the real NEST login dialog, recognizes an existing session, and automatically opens the server-protected player at `/api/signals?asset=index` after authorization. Running at the top level on NEST avoids embedded-page cookie restrictions. The existing Spotify redirect URI is preserved; only the known OAuth callback parameters are forwarded.

The server validates the active NEST session, uses its verified district email, and grants staff at exactly `@bethelsd.org`. Other district users must match the current leadership directory's email and one of five exact, case-insensitive roles: Assistant Manager, Division Manager, Chief Executive Officer, Chief Financial Officer, or Chief Operations Officer. The existing authenticated school bridge reads Imported!B2:F; position D and email F drive this check. No leadership list is sent to the Signals browser. Manual accounts and other owner email exceptions do not automatically receive Signals permission.

Player HTML and JavaScript require server authorization and are never cached. A successful check issues a 60-second HMAC grant tied to the same NEST session for loading the player files; file requests never extend it. The player inherits only that grant's remaining time before its next fresh check. Temporary school-service failures retry within a 55-second request deadline and display retry guidance, not a sign-in link. The page checks access at start and at least once per minute while running, stopping and disconnecting playback if permission cannot be verified. Menu visibility is convenience only; direct requests receive the same server check. Existing NEST account-registration rules are unchanged.

The shared public Spotify Client ID is configured in the player. Managers choose Connect Spotify without entering application credentials. Existing tokens from a different Client ID are cleared before reconnection. Moving playback into the authenticated NEST player requires connecting Spotify once again on the classroom browser. Keep the Spotify redirect URI `https://signals.gknest.org/`. Spotify's OAuth code is forwarded to the NEST entry page and the original PKCE state check still applies. No Spotify client secret is used.

Deploy the NEST endpoint before the Sites wrapper. Checks: npm test plus signed-out production endpoint checks. Real NEST login and Spotify playback require verification on an authorized classroom device.

Start signals activates the prepared Spotify browser audio element synchronously in the click. Audio stays online in the NEST browser player; no native Spotify app is launched or required. Reopening the page requires another Start click. Cleanup catches up any time during a non-silent block’s last six minutes and stays at 80% volume (except announcement suppression). Completion is recorded only after local playback confirmation, or when the same cleanup context is already playing on this player. Autoplay and playback failures stop scheduling and expose a retryable error.

Before transfer, Signals waits for its exact SDK device ID in Spotify’s available devices and confirms it is active before playback commands. Temporary transfer 404s retry up to three times; failures clear stale connection state for the next Start click. It never falls back to another account device. Volume uses the local SDK instead of another device-targeted API request.

Transitions catch up from the preceding block’s end until the next block’s cleanup begins, with completion markers preventing repeats. Access-check delays use a fresh timestamp. The audio panel records confirmed cleanup/period playback; second-period announcement muting lasts five minutes and displays its own status and sound-resume time.

An active planning block starts J&M Chill Folk directly, independent of neighboring lunch assignments and persisted transition markers. Starting after a refresh checks local playback and resumes Chill Folk when needed. Planning uses Chill Folk until its final six minutes, when an exit cleanup cue plays if the next block is neither planning nor lunch. Planning followed by lunch, more planning, or no block retains Chill Folk.

Lunch rows adjacent to planning use planning music when Signals starts during them, while suppressing lunch cleanup cues. The interface calls these planning music blocks instead of silent lunch.

Embedded playlist mode is the default for testing. It uses Spotify’s public iframe controller, with no developer OAuth or Web API calls, while retaining the NEST access check and schedule. Each cue loads the playlist and requests play; an unconfirmed request is labeled selected rather than confirmed. The visible player provides manual Play if autoplay is blocked. Full music versus previews and cross-browser autoplay require real-account testing. Five-minute announcements pause/resume the embed; the iframe API has no volume control, so use computer volume. Stop/access failure pauses the embed. Connected Spotify remains selectable; switching modes stops playback and reloads. Completion markers are separate in embedded mode.

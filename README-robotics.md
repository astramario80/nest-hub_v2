# CTSO Robotics in Division HQ

The CTSO HQ gains a Robotics tab for active/inactive membership, accepted FIRST youth registration, parent consent, roster matching and reminder previews. Other divisions retain their current tabs. Assignment management stays in the existing Trip-o-meter tab and existing tracker storage. This change does not migrate assignment scores back into Google Sheets.

Only Mario's existing owner identities and current CTSO Chief Executive Officer, Chief Financial Officer, and Chief Operations Officer assignments can edit CTSO assignments or open Robotics. The existing plural `Chief Operations Officers` title is supported. Executive Vice-President, liaisons, general school administrators, and delegated tracker editors do not gain Robotics or CTSO assignment editing. Current roster membership and roles are checked on every protected school request. CTSO edit delegation is disabled; other divisions retain their existing permissions.

## Data

The school bridge reads the original CTSO Trip-o-meter specified in `PERIODS.CTSO` and the recovered POW specified in `ROBOTICS_POW`. The uploaded XLSX is a reference, not an import or write target. Club status writes update exclusive Active/Inactive booleans in CTSO `NEST™MembershipStatus!A:B` and POW `MembershipForm!A:B`, locating the member by student ID and full normalized name. Ambiguous or missing POW matches block status editing. The membership refresh pulls A:E from POW. H:J and L:M in the CTSO sheet remain the FIRST status and summary outputs.

FIRST imports use the supplied original Accepted Youth parser. Pending invitations, pending applications, declined members, and team leadership are excluded. Empty or malformed imports leave existing data intact. Accepted youth names and consent are saved in `FRC Roster Raw!A:D`, with FIRST email in column E. Unknown consent remains unknown and receives no waiver reminder. Name matching uses complete normalized names rather than the original four-character fuzzy match; unmatched names are listed for review. FIRST is not queried automatically. The displayed import timestamp records website imports; existing saved rosters have an unknown timestamp.

Reminder addresses come from the live NEST CTSO roster, not the potentially misaligned email column in the uploaded membership sheet. Student ID and district email must agree before notification delivery. Only active members qualify. Join and waiver reminders are separate groups; Both sends the appropriate reminder to each group. Test sends both messages only to the signed-in account; a manual account without a real sending address cannot receive a test. Recipients and messages must be previewed and explicitly confirmed in the UI. Email is sent by the deploying school bridge account through MailApp. No emails were sent during implementation or automated testing.

Previews bind to the actor and full membership/roster revision for ten minutes. A send claims its preview before delivery, so retrying the same batch returns its recorded result without resending. A delivery timeout must be checked before creating another preview. The daily MailApp quota is checked first. Membership writes require a matching content revision and run under the school bridge script lock. Spreadsheet edits and scripts in other projects do not share that lock; live school verification is required. Cross-workbook writes cannot be atomic: POW is written first, and Refresh from POW reconciles a partially saved status.

# Private NEST access diagnostics

Live site: https://gknest.org/profile#diagnostics. Open from Profile → Access diagnostics. Only mario@memberhq.net, mpenalver@bethelsd.org and astramario@gmail.com have read access; the Google bridge freshly validates the active owner session. Other leadership roles are not granted read access.

Records start with this release. A private standalone Google spreadsheet is created by the school bridge when the first metadata batch arrives. Non-owner permissions are removed at creation. No log is placed in the shared service/student workbook. Up to5,000 ring-buffer rows are retained; dashboard filters support24hours,7days and all retained records.

Server tracking wraps sign-in, service requests, hiring, tracker, signals, division, leadership, fabrication, lunch and profile APIs. A request ID is returned in X-NEST-Request-ID. Server events record action, HTTP status, elapsed processing time, username source and a fixed status code. Browser metadata capture on common sign-in pages records network response wait, timestamp, phase and request ID. Browser reports are authenticated, validated and annotated from the verified school session. Initial failed sign-ins still have server records; attempted usernames are explicitly unverified. Requests that never reach the server can only be reported by a signed-in browser after connectivity recovers. Whole-page rendering/third-party script timings are not measured.

No raw messages, stack traces, request bodies, passwords, verification codes, cookies, IPs, ticket text or client contacts are stored. A session token may be transported transiently to the existing private bridge for username verification; it is discarded by the persisted column projection. Nothing is sent to other people.

Server recording uses Vercel waitUntil and a bounded in-memory batch queue; it is best-effort when the school bridge or function runtime is unavailable. Browser reports use a bounded sessionStorage metadata queue, retry after reporting failures and clear on logout/account change. Old-account metadata is not sent as a new account. The diagnostics endpoint is excluded to prevent recursive logging. Storage reserves ring slots under brief locks, performs Google I/O outside the locks and never holds a lock during spreadsheet creation or writes.

The dashboard merges server/browser phases by request ID and displays both waits, filters area/account/outcome/time, computes average and95th percentile, and offers Copy error, Copy details and Copy filtered report with selectable-text fallback. Only the latest500 rows render for responsive browsing; copied reports include all filtered matches. Read failure or identity change clears private data.
